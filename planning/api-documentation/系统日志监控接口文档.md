# 系统日志监控接口文档

## 1. 接口概览

### 1.1 系统日志监控

| 方法 | 路径 | 功能简述 | 认证要求 |
|------|------|---------|---------|
| GET | `/api/v1/system_logs/` | 查询告警日志列表 | 管理员及以上 |
| GET | `/api/v1/system_logs/stats` | 获取日志统计概览 | 管理员及以上 |
| POST | `/api/v1/system_logs/batch_resolve` | 批量标记日志为已处理 | 管理员及以上 |
| GET | `/api/v1/system_logs/{log_id}` | 查看单条日志详情 | 管理员及以上 |
| POST | `/api/v1/system_logs/{log_id}/resolve` | 单条标记为已处理 | 管理员及以上 |
| DELETE | `/api/v1/system_logs/{log_id}` | 删除指定日志 | 管理员及以上 |

---

## 2. 枚举与常量定义

| 常量/枚举 | 值 | 说明 |
|-----------|-----|------|
| 日志级别 `level` | `"WARN"` | 警告 |
| | `"ERROR"` | 错误 |
| | `"CRITICAL"` | 严重 |
| 默认分页 | `skip=0, limit=20` | 列表接口默认值，`limit` 上限 `100` |

---

## 3. 统一封装返回结果

### 3.1 成功返回

后端**未**对成功响应做统一封装。接口成功时，直接返回对应 Schema 序列化后的 JSON，HTTP 状态码通常为 `200`（删除操作为 `204`）。

### 3.2 错误返回

所有错误响应均由全局异常处理器统一封装，结构如下：

```json
{
  "code": <HTTP状态码>,
  "message": "错误描述",
  "detail?": "可选的详细错误信息"
}
```

| 场景 | HTTP 状态码 | `message` | 说明 |
|------|------------|-----------|------|
| 参数校验失败 | `422` | 请求参数校验失败 | 附 `detail: [...]` 具体字段错误 |
| 未认证 | `401` | 缺少认证令牌 / 令牌校验失败 | — |
| 权限不足 | `403` | 权限不足 | 非管理员访问 |
| 日志不存在 | `404` | 日志不存在 | — |
| 未预料异常 | `500` | 服务器内部错误 | 兜底，不暴露堆栈 |

---

## 4. 认证说明

所有接口均需在请求头中携带访问令牌：

```
Authorization: Bearer <access_token>
```

令牌失效或缺失时，返回 `401`：

```json
{
  "code": 401,
  "message": "缺少认证令牌"
}
```

**权限要求**：所有日志接口均要求当前用户为**管理员及以上**（`permission ≥ 1`）。普通用户调用将返回 `403`。

---

## 5. 公共响应类型

### `SystemLogResponse`

| 名称 | 类型 | 说明 |
|------|------|------|
| id | integer | 日志 ID |
| level | string | 日志级别：`WARN` / `ERROR` / `CRITICAL` |
| module | string \| null | 日志来源模块名（logger 名称） |
| message | string | 日志内容 |
| exception | string \| null | 异常堆栈文本 |
| trace_id | string \| null | 请求链路追踪 ID |
| user_id | integer \| null | 触发该日志的操作用户 ID |
| ip | string \| null | 客户端 IP |
| extra | object \| null | JSONB 结构化上下文（请求参数、环境变量等） |
| is_resolved | boolean | 是否已处理 |
| resolved_at | string(datetime) \| null | 处理时间 |
| resolved_by | integer \| null | 处理人用户 ID |
| created_at | string(datetime) | 日志创建时间 |

### `SystemLogListResponse`

| 名称 | 类型 | 说明 |
|------|------|------|
| items | `SystemLogResponse[]` | 日志列表 |
| total | integer | 符合条件的日志总数（用于分页计算） |

### `SystemLogStatsResponse`

| 名称 | 类型 | 说明 |
|------|------|------|
| total | integer | 日志总条数 |
| total_unresolved | integer | 未处理日志条数 |
| warn_count | integer | `WARN` 级别条数 |
| error_count | integer | `ERROR` 级别条数 |
| critical_count | integer | `CRITICAL` 级别条数 |

## 6. 单接口详细定义

### 6.1 日志列表

---

### GET `/api/v1/system_logs/`

- **功能**：查询系统告警日志列表（分页 + 多条件筛选）
- **认证**：管理员及以上（`permission ≥ 1`）

#### Query 参数

| 名称 | 类型 | 必填 | 约束 | 说明 |
|------|------|------|------|------|
| skip | integer | 否 | `≥ 0`，默认 `0` | 跳过数量 |
| limit | integer | 否 | `1~100`，默认 `20` | 返回数量上限 |
| level | string | 否 | `WARN`/`ERROR`/`CRITICAL` | 按日志级别筛选 |
| is_resolved | boolean | 否 | — | 按是否已处理筛选 |
| module | string | 否 | — | 按模块名模糊筛选 |
| created_after | string(datetime) | 否 | ISO 8601 格式 | 创建时间起始（含） |
| created_before | string(datetime) | 否 | ISO 8601 格式 | 创建时间截止（含） |

#### Headers

| 名称 | 必填 | 说明 |
|------|------|------|
| Authorization | 是 | `Bearer <access_token>` |

#### 成功响应

- **状态码**：`200`
- **返回**：`SystemLogListResponse`

#### 失败响应

| 状态码 | 原因 |
|--------|------|
| 403 | 权限不足 |
| 422 | 请求参数校验失败 |

### 6.3 批量标记已处理

---

### POST `/api/v1/system_logs/batch_resolve`

- **功能**：批量将指定日志标记为已处理
- **认证**：管理员及以上（`permission ≥ 1`）

#### Headers

| 名称 | 必填 | 说明 |
|------|------|------|
| Authorization | 是 | `Bearer <access_token>` |

#### RequestBody

| 名称 | 类型 | 必填 | 约束 | 说明 |
|------|------|------|------|------|
| ids | integer[] | 是 | 至少 1 个元素 | 要标记的日志 ID 列表 |

#### 成功响应

- **状态码**：`200`

```json
{
  "resolved_count": 3
}
```

#### 失败响应

| 状态码 | 原因 |
|--------|------|
| 403 | 权限不足 |
| 422 | 请求参数校验失败（如 `ids` 为空数组） |
