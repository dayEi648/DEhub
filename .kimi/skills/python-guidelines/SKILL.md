# Python Development Principles

1. Clarity Above All

	- Write explicit code. Never hide logic or intent behind implicit behavior.

	- Prefer simple over complex, and complex over complicated.

	- Favor flat structures over deeply nested ones. Keep code sparse, not dense.

	- Readability is mandatory, not optional.

2. Reliability & Error Handling

	- Never silently ignore or swallow errors unless explicitly instructed to do so.

	- When facing ambiguity, choose the explicit and conservative path. Do not guess.

3. Design Philosophy

	- There should be one clear, obvious way to implement a solution. If multiple options exist, select the most explicit and readable one.

	- Favor practical solutions, but never sacrifice clarity or correctness for convenience.

	- Use namespaces, modules, and encapsulation generously.

4. Implementation Quality

	- If you cannot explain the implementation in simple terms, it is a bad approach and should be rewritten.

	- If the logic is easy to explain clearly, it is likely a good approach.
