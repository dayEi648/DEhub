# 用户接口文档

## 1. 接口概览

### 1.1 用户管理

| 方法 | 路径 | 功能简述 | 认证要求 |
|------|------|---------|---------|
| POST | `/api/v1/users/` | 创建用户 | 管理员及以上 |
| GET | `/api/v1/users/{user_id}` | 获取单个用户 | 登录用户（已注销用户仅管理员可查看）|
| GET | `/api/v1/users/` | 获取用户列表 | 管理员及以上 |
| PUT | `/api/v1/users/{user_id}` | 更新用户 | 登录用户 |
| DELETE | `/api/v1/users/{user_id}` | 注销用户（逻辑删除） | 管理员或本人 |
| DELETE | `/api/v1/users/{user_id}/hard` | 硬删除用户 | 管理员及以上 |
| POST | `/api/v1/users/login` | 用户登录 | 无需认证 |
| POST | `/api/v1/users/refresh-token` | 刷新访问令牌 | 无需认证 |
| POST | `/api/v1/users/logout` | 用户登出 | 登录用户 |
| POST | `/api/v1/users/register` | 用户注册 | 无需认证 |
| POST | `/api/v1/users/me/change-password` | 修改密码 | 登录用户 |


## 2. 枚举与常量定义

| 常量/枚举 | 值 | 说明 |
|-----------|-----|------|
| 用户权限 `permission` | `0` | 普通用户 |
| | `1` | 管理员 |
| | `2` | 超级管理员 |
| Token 类型 | `"access"` | 访问令牌 |
| | `"refresh"` | 刷新令牌 |
| 默认分页 | `skip=0, limit=20` | 列表接口默认值，limit 上限 100 |

## 3. 统一封装返回结果

### 3.1 成功返回

后端**未**对成功响应做统一封装。接口成功时，直接返回对应 Schema 序列化后的 JSON，HTTP 状态码通常为 `200`（部分写操作为 `201`/`204`）。

### 3.2 错误返回

所有错误响应均由全局异常处理器统一封装，结构如下：

```json
{
  "code": <HTTP状态码>,
  "message": "错误描述",
  "detail?": "可选的详细错误信息"
}
```

| 场景 | HTTP 状态码 | `message` | 说明 |
|------|------------|-----------|------|
| 参数校验失败 | `422` | 请求参数校验失败 | 附 `detail: [...]` 具体字段错误 |
| 业务逻辑错误 | `400` / `401` / `403` / `404` | 视具体接口而定 | 如用户名已存在、权限不足等 |
| 数据库异常 | `500` | 数据库异常，请稍后重试 | — |
| 未预料异常 | `500` | 服务器内部错误 | 兜底，不暴露堆栈 |

**示例 — 参数校验失败：**

```json
{
  "code": 422,
  "message": "请求参数校验失败",
  "detail": [
    {
      "loc": ["body", "email"],
      "msg": "value is not a valid email address",
      "type": "value_error.email"
    }
  ]
}
```

**示例 — 权限不足：**

```json
{
  "code": 403,
  "message": "权限不足，需要超级管理员权限"
}
```

## 4. 认证说明

除 `POST /api/v1/users/login`、`POST /api/v1/users/register` 和 `POST /api/v1/users/refresh-token` 外，其余接口均需在请求头中携带访问令牌：

```
Authorization: Bearer <access_token>
```

令牌失效或缺失时，返回 `401`：

```json
{
  "code": 401,
  "message": "缺少认证令牌"
}
```

## 6. 单接口详细定义

### 6.1 用户管理

---

### POST `/api/v1/users/`

- **功能**：创建用户
- **认证**：管理员及以上（`permission ≥ 1`）

#### Headers

| 名称 | 必填 | 说明 |
|------|------|------|
| Authorization | 是 | `Bearer <access_token>` |

#### RequestBody

| 名称 | 类型 | 必填 | 约束 | 说明 |
|------|------|------|------|------|
| username | string | 是 | 3~64 字符 | 用户名 |
| email | string | 是 | 有效邮箱格式 | 邮箱 |
| password | string | 是 | 6~128 字符 | 密码 |
| permission | integer | 否 | `0~2`，默认 `0` | 权限级别；**管理员（1）传入 `2` 将被拒绝** |
| personal_profile | string | 否 | — | 个人简介 |

#### 成功响应

- **状态码**：`201`
- **返回**：`UserResponse`

| 名称 | 类型 | 说明 |
|------|------|------|
| id | integer | 用户 ID |
| username | string | 用户名 |
| email | string | 邮箱 |
| created_at | string(datetime) | 创建时间 |
| permission | integer | 权限级别 |
| is_deleted | boolean | 是否已注销 |
| avatar_url | string \| null | 头像 URL |
| personal_profile | string \| null | 个人简介 |

#### 失败响应

| 状态码 | 原因 |
|--------|------|
| 403 | 权限不足（当前用户非管理员，或管理员尝试创建超级管理员） |
| 400 | 用户名或邮箱已存在 |
| 422 | 请求参数校验失败 |

- **认证**：登录用户

| 名称 | 类型 | 必填 | 说明 |
|------|------|------|------|
| user_id | integer | 是 | 用户 ID |

#### Headers

| 名称 | 必填 | 说明 |
|------|------|------|
| Authorization | 是 | `Bearer <access_token>` |

#### 成功响应

- **状态码**：`200`

#### 失败响应

| 状态码 | 原因 |
|--------|------|
| 404 | 用户不存在 |
| 403 | 用户已注销，仅管理员可查看 |

### GET `/api/v1/users/`

- **功能**：获取用户列表（支持分页与筛选）
- **认证**：管理员及以上（`permission ≥ 1`）
- **权限说明**：该接口是后台管理接口，不作为普通用户侧的公开用户搜索/作者选择接口使用；如后续需要公开用户查询，应新增仅返回 `UserBriefInfo` 的独立接口。

#### Query 参数

| 名称 | 类型 | 必填 | 约束 | 说明 |
|------|------|------|------|------|
| skip | integer | 否 | 默认 `0` | 跳过数量 |
| limit | integer | 否 | `1~100`，默认 `20` | 返回数量上限 |
| include_deleted | boolean | 否 | 默认 `false` | 是否包含已注销用户 |
| username | string | 否 | — | 用户名模糊筛选 |
| email | string | 否 | — | 邮箱模糊筛选 |
| permission | integer | 否 | `0~2` | 权限值筛选 |

#### Headers

| 名称 | 必填 | 说明 |
|------|------|------|
| Authorization | 是 | `Bearer <access_token>` |

#### 成功响应

- **状态码**：`200`
- **返回**：`UserListResponse`

| 名称 | 类型 | 说明 |
|------|------|------|
| items | `UserResponse[]` | 用户列表 |
| total | `integer` | 符合条件的用户总数（用于分页计算） |

#### 失败响应

| 状态码 | 原因 |
|--------|------|
| 403 | 权限不足 |
| 422 | 请求参数校验失败 |

---

### PUT `/api/v1/users/{user_id}`

- **功能**：更新用户信息（含头像上传）
- **认证**：本人或管理员及以上

#### Path 参数

| 名称 | 类型 | 必填 | 说明 |
|------|------|------|------|
| user_id | integer | 是 | 用户 ID |

#### Headers

| 名称 | 必填 | 说明 |
|------|------|------|
| Authorization | 是 | `Bearer <access_token>` |

#### RequestBody

`Content-Type: multipart/form-data`

| 名称 | 类型 | 必填 | 约束 | 说明 |
|------|------|------|------|------|
| user_in | JSON 字符串 | 是 | — | 用户更新请求的 JSON 字符串，各字段全可选 |
| file | file | 否 | 最大 20MB，后端自动压缩至 5MB 以下 | 头像文件，前端仅支持文件上传，不允许自填 `avatar_url`；仅修改基础信息时可不传 |

> 注：FastAPI 接受 `UploadFile` 与 `UserUpdate` 同时存在时，请求体为 `multipart/form-data`。后端不再接收 `avatar_url` 作为更新入参；其中 `user_in` 各字段如下（全可选）：

| 名称 | 类型 | 约束 | 说明 |
|------|------|------|------|
| username | string | 3~64 字符 | 用户名 |
| email | string | 有效邮箱格式 | 邮箱 |
| password | string | 6~128 字符 | 密码 |
| permission | integer | `0~2` | 权限级别；普通用户传入该字段将被拒绝 |
| personal_profile | string | — | 个人简介 |

#### 成功响应

- **状态码**：`200`
- **返回**：`UserResponse`

#### 失败响应

| 状态码 | 原因 |
|--------|------|
| 404 | 用户不存在 |
| 403 | 权限不足 / 无权修改权限字段 |
| 422 | 请求参数校验失败 |

### POST `/api/v1/users/login`

- **功能**：用户登录
- **认证**：无需认证

#### RequestBody

| 名称 | 类型 | 必填 | 约束 | 说明 |
|------|------|------|------|------|
| account | string | 是 | 3~255 字符 | 邮箱或用户名 |
| password | string | 是 | 6~128 字符 | 密码 |
| is_remember | boolean | 否 | 默认 `false` | 是否记住登录 |

> `account` 校验规则：含 `@` 时按邮箱格式校验；否则按用户名长度 `3~64` 校验。

#### 成功响应

- **状态码**：`200`

| 名称 | 类型 | 说明 |
|------|------|------|
| access_token | string | 访问令牌 |
| refresh_token | string \| null | 刷新令牌（`is_remember=true` 时返回） |
| token_type | string | 固定值 `"Bearer"` |
| user | UserResponse | 用户信息 |
| access_token_expires_in | integer | 访问令牌有效期（分钟），取自后端配置 `ACCESS_TOKEN_EXPIRE_MINUTES` |
| refresh_token_expires_in | integer \| null | 刷新令牌有效期（分钟），取自后端配置 `REFRESH_TOKEN_EXPIRE_MINUTES`（`is_remember=true` 时返回）；刷新成功后会签发新的 refresh token |

#### 失败响应

| 状态码 | 原因 |
|--------|------|
| 401 | 用户不存在或密码错误 / 用户已注销 |
| 422 | 请求参数校验失败 |

---

### POST `/api/v1/users/refresh-token`

- **功能**：刷新访问令牌
- **认证**：无需认证

#### RequestBody

| 名称 | 类型 | 必填 | 约束 | 说明 |
|------|------|------|------|------|
| refresh_token | string | 是 | 最小 1 字符 | 刷新令牌 |

#### 成功响应

- **状态码**：`200`
- **返回**：同 `POST /api/v1/users/login` 成功响应

#### 失败响应

| 状态码 | 原因 |
|--------|------|
| 401 | 刷新令牌不能为空 / 令牌已注销 / 令牌校验失败 / 令牌类型错误 / 用户不存在 / 用户已注销 |

> **前端注意**：刷新成功后，旧的 `refresh_token` 会立即被加入黑名单失效，同时签发一对全新的 `access_token` + `refresh_token`。前端必须同时更新本地存储的两个令牌，旧 `refresh_token` 不可再次使用。

### POST `/api/v1/users/me/change-password`

- **功能**：修改当前登录用户密码
- **认证**：登录用户（仅支持修改自己的密码）
- **后端决策**：修改成功后，后端自动从请求头提取当前 `access_token` 并使其失效，同时使该用户所有已签发的 Token 全部失效，需重新登录

#### Headers

| 名称 | 必填 | 说明 |
|------|------|------|
| Authorization | 是 | `Bearer <access_token>` |

#### RequestBody

| 名称 | 类型 | 必填 | 约束 | 说明 |
|------|------|------|------|------|
| old_password | string | 是 | 6~128 字符 | 旧密码 |
| new_password | string | 是 | 6~128 字符，不能与 `old_password` 相同 | 新密码 |

#### 成功响应

- **状态码**：`204`
- **返回**：无

#### 失败响应

| 状态码 | 原因 |
|--------|------|
| 401 | 旧密码错误 |
| 400 | 新密码不能与旧密码相同 |
| 422 | 请求参数校验失败 |
