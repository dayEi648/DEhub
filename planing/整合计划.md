# OpenAPI 智能助手整合计划

## 1. 固定边界

### 1.1 整合目标

将 `SmartApiAgent/backend/` 中的 OpenAPI 文档解析、知识库检索和接口调用辅助能力整合进个人博客网站。整合完成后，管理员可以在博客网站内维护共享 OpenAPI 知识库，并在现有 AI 对话中让 AI 基于知识库回答接口问题或生成调用示例。

### 1.2 不变约束

1. 后端架构以博客网站 `backend/` 为准，不迁移 SmartApiAgent 的独立应用壳。
2. AI 对话继续使用博客现有阻塞式 `POST /api/v1/ai_chat/chat`，不引入 SSE。
3. 向量知识库统一使用 PostgreSQL + pgvector，不使用 Chroma。
4. 对话记忆继续使用博客现有 `ChatService`、`ai_conversations`、`conversation_messages` 和 Redis checkpointer。
5. OpenAPI 文档解析、知识库更新、知识库检索、代码生成、代码检查、子 Agent 编排等能力只允许管理员及以上使用。
6. 普通用户不能通过 REST 接口、Agent 工具、Prompt 或前端入口知道或触发 OpenAPI 私有知识库能力。
7. Agent 编排、工具注册、Prompt 组装、权限治理全部沿用博客现有 `create_agent`、`ToolRegistry`、`PromptAssemblyMiddleware` 体系。
8. 前端知识库维护入口要放在 AI 对话页的管理员操作区域，后台侧栏只作为辅助入口。

## 2. 后端完成摘要

### 2.1 已完成能力

后端已经完成 OpenAPI 智能助手整合的主体开发，当前后端侧按博客架构承载以下能力：

1. 新增 `openapi_knowledge` 管理接口，用于管理员上传、查询、检索和删除 OpenAPI 知识库数据。
2. 新增 OpenAPI 文档元数据和端点向量数据模型，使用 PostgreSQL + pgvector 存储共享知识库。
3. 文档表自身承载解析状态，状态为 `pending`、`processing`、`completed`、`failed`。
4. 上传接口返回 `document_id`，前端通过文档详情接口轮询状态，不使用独立 task 接口。
5. 解析服务支持 JSON、YAML、OpenAPI 3.x 基础结构、Swagger 2.0 基础结构、path-level parameters 和 Swagger 2.0 body 参数。
6. Embedding 服务复用博客现有 Embedding 客户端，支持端点向量同步、检索和删除。
7. OpenAPI 检索和调用示例工具注册为管理员工具，仅 `ToolScope.ADMIN` 可见。
8. `permission_level` 已进入 AI 对话状态，Prompt 仅在管理员及以上权限下追加 OpenAPI 能力说明。
9. 接口响应使用专用 schema，避免向前端泄露 `content_hash`、`embedding` 等内部字段。
10. 后端接口文档已补充到 `planing/接口文档/OpenAPI知识库接口文档.md`。

### 2.2 后端接口摘要

| 方法 | 路径 | 功能 | 权限 |
|------|------|------|------|
| `POST` | `/api/v1/openapi_knowledge/documents/upload` | 上传 OpenAPI 文档并启动解析 | 管理员及以上 |
| `GET` | `/api/v1/openapi_knowledge/documents` | 分页查看文档列表 | 管理员及以上 |
| `GET` | `/api/v1/openapi_knowledge/documents/{document_id}` | 查看文档详情和解析状态 | 管理员及以上 |
| `DELETE` | `/api/v1/openapi_knowledge/documents/{document_id}` | 删除文档及其端点向量 | 管理员及以上 |
| `GET` | `/api/v1/openapi_knowledge/endpoints` | 分页查看端点列表 | 管理员及以上 |
| `GET` | `/api/v1/openapi_knowledge/search` | 手动检索 OpenAPI 知识库 | 管理员及以上 |
| `DELETE` | `/api/v1/openapi_knowledge/endpoints/{endpoint_id}` | 删除单个端点向量 | 管理员及以上 |

### 2.3 后端验收基线

1. 普通用户访问 OpenAPI 管理接口应返回 `403`。
2. 普通用户工具列表不包含 OpenAPI 工具。
3. 普通用户 Prompt 不包含 OpenAPI、接口知识库、代码生成子 Agent 等私有能力描述。
4. 管理员 Prompt 包含 OpenAPI 能力边界和禁止编造接口的约束。
5. 文档解析失败必须写入 `failed` 和 `error_message`。
6. 端点向量写入失败不能静默标记为成功。
7. 删除文档必须级联删除端点向量。
8. AI 对话、博客 RAG、联网搜索、隐藏消息查看等既有能力不应回归。

## 3. 前端整合目标

### 3.1 管理员目标

1. 管理员可以从 AI 对话页的合理位置进入 OpenAPI 知识库维护页面。
2. 管理员可以上传 OpenAPI 文档，并清楚看到解析和向量化状态。
3. 管理员可以查看文档列表、端点列表、手动检索结果、失败原因和删除确认。
4. 管理员在维护知识库后，可以回到 AI 对话页使用阻塞式对话询问接口用法。
5. 文档上传、解析、轮询、删除和刷新过程必须有明确 loading、disabled、错误和空态反馈。

### 3.2 普通用户目标

1. 普通用户继续使用原有 AI 对话页面。
2. 普通用户不看到知识库入口、知识库文案、OpenAPI 能力说明或后台链接。
3. 普通用户直接访问 `/admin/openapi-knowledge` 时被 `AuthGuard requireAdmin` 拦截。
4. 普通用户侧不应因为新增前端代码增加无关请求或影响对话发送流程。

## 4. 前端信息架构

### 4.1 路由规划

| 路由 | 页面 | 保护方式 | 说明 |
|------|------|----------|------|
| `/ai-chat` | 现有 `AIChatPage` | 登录用户 | 在管理员工具区新增知识库入口 |

新增页面挂载在现有 `/admin/*` 路由下，由 `AdminLayout` 和 `AdminDashboard` 统一承载，避免创建第二套后台布局。

### 4.2 入口位置

主入口放在 `AIChatPage` 的对话面板 header 管理员操作区域，建议与现有“显示系统/工具消息”开关同级展示。

入口规则：

1. 使用 `currentUser.permission >= 1` 判断是否渲染。
2. 管理员看到“接口知识库”或“OpenAPI 知识库”入口按钮。
3. 点击后跳转到 `/admin/openapi-knowledge`。
4. 普通用户不渲染入口按钮，也不渲染任何解释性文案。
5. 不在普通用户 bundle 之外强制要求代码分包，但普通用户页面运行时不能触发 OpenAPI API 请求。

辅助入口放在后台侧栏 `Sidebar`：

1. 在日志、用户、内容、设置之间或内容管理附近新增“接口知识库”。
2. 该入口只存在于 `/admin/*` 后台布局内，作为已进入后台后的导航。
3. 入口不是普通用户可发现路径，实际权限仍由 `AuthGuard requireAdmin` 和后端接口共同兜底。

### 4.3 页面布局

`OpenAPIKnowledgePage` 采用管理工作台布局，重点是操作效率和状态可见性：

1. 顶部为页面标题、说明、刷新按钮和最近处理状态摘要。
2. 顶部或左上区域放上传卡片，支持拖拽或文件选择。
3. 主体使用左右分栏：左侧为文档列表，右侧为端点列表和检索区。
4. 桌面端建议三块区域：上传与状态概览、文档表格、端点/检索详情。
5. 移动端改为 Tab：`文档`、`端点`、`检索`，上传入口固定在顶部或抽屉内。
6. 不引入与博客现有设计冲突的新视觉体系，复用 `index.css` 的变量、按钮、表格和卡片风格。

## 7. 前端关键流程

### 7.1 上传与轮询

上传流程：

1. 管理员选择 `.json`、`.yaml` 或 `.yml` 文件。
2. 前端校验文件扩展名、空文件和 10MB 大小限制。
3. 展示文件名、大小、上传说明和“上传后会更新共享知识库”的管理员提示。
4. 明确提示重复文件会覆盖旧文档及其端点向量，避免管理员误以为会并存。
5. 点击上传后立即禁用上传按钮，防止重复提交。
6. 上传成功后拿到 `document_id`，立即刷新文档列表，不能只在本地追加记录，因为重复上传可能导致旧文档被覆盖。
7. 对该 `document_id` 启动轮询 `GET /documents/{document_id}`。
8. 状态为 `completed` 时停止轮询，刷新文档列表和端点列表。
9. 状态为 `failed` 时停止轮询，展示 `error_message`，并允许管理员重新上传修正后的文档。

轮询策略：

1. 使用普通 HTTP 请求，不使用 SSE。
2. 建议间隔 2 秒。
3. 页面卸载、切换文档、重新上传、手动刷新时必须清理旧 interval。
4. 每轮请求使用 `AbortController` 或请求序号，防止旧响应覆盖新状态。
5. 轮询最长建议 5 分钟；超时后停止自动轮询并提示管理员手动刷新。
6. 同一页面实例同一时间只允许一个 active polling document，避免请求风暴。

### 7.2 并发与一致性防护

必须显式处理以下并发场景：

| 场景 | 前端处理 |
|------|----------|
| 管理员连续点击上传 | 上传按钮 loading + disabled，直到请求结束 |
| 上传中又选择新文件 | 允许替换待上传文件，但已发出的上传请求不能被重复提交 |
| 上传重复文件 | 按后端覆盖语义处理，上传成功后全量刷新文档和端点列表 |
| 文档正在 `pending` 或 `processing` | 禁用该文档删除按钮，提示“解析完成或失败后再删除” |
| 文档删除中 | 禁用该行操作按钮，避免重复删除 |
| 端点删除中 | 禁用该端点操作按钮，并在成功后局部刷新 |
| 轮询请求未返回时触发刷新 | 取消旧请求或丢弃旧响应，只接受最新 requestId |
| 搜索条件快速变化 | 搜索按钮触发式查询，不做输入即请求；提交时记录 requestId |
| 管理员离开页面 | 清理 interval、AbortController 和组件状态更新 |

第一版至少保证单页面内不会重复上传、重复删除、重复轮询。跨浏览器标签页的全局互斥可作为增强项，后续再通过 `BroadcastChannel` 或 `localStorage` 协调。

### 7.3 文档列表

文档列表功能：

1. 支持分页加载，默认按创建时间或更新时间倒序。
2. 支持按状态过滤。
3. 每行展示文件名、状态、端点数、分片数、失败原因摘要、创建时间、更新时间。
4. 状态使用统一 badge：`pending`、`processing`、`completed`、`failed`。
5. `failed` 状态可展开查看完整错误。
6. 删除文档必须二次确认。
7. 删除成功后刷新文档列表、端点列表和搜索结果。

删除限制：

1. `pending` 和 `processing` 状态下前端禁用删除。
2. 即使后端允许删除处理中记录，前端第一版仍保持禁用，避免解析任务和删除动作并发造成展示不一致。
3. 如果删除接口返回 `404`，前端按已删除处理并刷新列表。

### 7.4 端点列表

端点列表功能：

1. 支持按 `document_id`、`method`、`tag` 过滤。
2. 支持分页，默认每页 50 条。
3. 展示 `method`、`path`、`summary`、`tags`、`operation_id`。
4. `content` 详情默认折叠，点击后展开。
5. 删除单个端点必须二次确认。
6. 删除端点后局部刷新当前页，并同步更新文档列表中的分片或端点统计。

展示要求：

1. HTTP 方法使用颜色 badge，但不引入过度花哨样式。
2. 长 path、summary、description 必须省略或换行，避免撑破布局。
3. 不展示 `embedding`、`content_hash` 等内部字段。

### 7.5 手动检索

检索功能：

1. 输入框参数为 `q`，空字符串禁用检索按钮。
2. 可选过滤项为 `top_k`、`method`、`document_id`。
3. `top_k` 默认 5，最大不超过接口文档限制。
4. 结果展示相似度、method、path、summary、content 摘要。
5. 无结果时展示“当前知识库未找到相关接口”。
6. 检索失败时展示接口错误，不清空上一轮成功结果，除非用户主动清除。

交互要求：

1. 检索是管理员调试知识库的工具，不替代 AI 对话。
2. 页面文案应提示“上传完成后，可回到 AI 对话中询问接口用法”。
3. 该提示只在管理员页面和管理员对话入口附近出现，普通用户不可见。

### 7.6 与 AI 对话页的关系

AI 对话页只做入口适配，不改变核心对话流程：

1. 不修改 `chatWithAI` 的阻塞式调用模型。
2. 不在 AI 对话页直接上传文档，避免对话输入区承担管理任务。
3. 管理员入口点击后跳转后台知识库页面。
4. 管理员从知识库页面返回对话页后，可直接通过现有输入框提问。
5. 普通用户对话页不出现 OpenAPI、接口知识库、RAG 知识库等相关字样。
6. 新增入口不能影响现有历史对话加载、删除对话、发送消息和隐藏消息开关。

## 8. 前端权限与安全

### 8.1 前端权限规则

1. 所有知识库入口渲染前都判断 `currentUser.permission >= 1`。
2. `/admin/openapi-knowledge` 继续由现有 `AuthGuard requireAdmin` 保护。
3. `OpenAPIKnowledgePage` 内部仍应做一次管理员判断，用于防止用户信息短暂缺失时误发请求。
4. `api/openapiKnowledge.ts` 不在模块初始化时自动发请求。
5. 401 和 403 使用现有 `request.ts` 行为处理，页面补充友好的权限失败提示。

### 8.2 数据安全规则

1. 前端不持久化 OpenAPI 文档内容到 `localStorage` 或 `sessionStorage`。
2. 错误提示不打印上传文件内容。
3. 控制台日志不输出完整接口文档或 token 示例。
4. 下载、导出、批量复制不是第一版功能，避免扩大敏感信息传播面。
5. 若后端返回字段超出接口文档，前端只使用白名单字段展示。

## 11. 风险与控制

### 11.1 权限泄露风险

风险：普通用户看到知识库入口、文案或触发相关 API。

控制：

1. 入口渲染、路由守卫和后端权限三层同时控制。
2. 普通用户路径测试必须覆盖 `/ai-chat` 和 `/admin/openapi-knowledge`。
3. AI 对话页普通用户文案不得出现 OpenAPI 或接口知识库描述。

### 11.2 并发请求风险

风险：上传、轮询、刷新、删除并发导致请求风暴或状态错乱。

控制：

1. 上传和删除按钮必须有 loading 锁。
2. 单页面只保留一个轮询任务。
3. 使用 requestId 或 AbortController 丢弃旧响应。
4. 页面卸载必须清理 interval 和异步状态更新。

### 11.3 处理中删除风险

风险：文档解析或向量化尚未完成时删除，前端展示与后端任务状态不一致。

控制：

1. `pending` 和 `processing` 文档前端禁用删除。
2. 删除前必须二次确认。
3. 删除后刷新全部相关列表。

### 11.4 对话页回归风险

风险：新增入口破坏 AI 对话页布局或发送流程。

控制：

1. 只在管理员操作区增加入口，不改 `chatWithAI` 调用模型。
2. 普通用户不渲染入口。
3. 前端回归测试覆盖消息发送、历史加载、删除对话、隐藏消息开关。

### 11.5 敏感信息展示风险

风险：OpenAPI 文档中包含内部接口、鉴权参数或示例 token。

控制：

1. 页面只对管理员开放。
2. 前端不持久化文档内容。
3. 不提供导出功能。
4. 错误日志和控制台不输出文件正文。

### 11.6 重复上传覆盖风险

风险：相同文件上传会覆盖旧文档及其端点向量，管理员如果没有感知，可能误判为新增了一份并行知识库。

控制：

1. 上传说明中明确提示重复文件的覆盖语义。
2. 上传成功后刷新文档列表和端点列表，不使用本地追加造成假并存。
3. 若后续需要保留多版本文档，应先调整后端版本策略，再调整前端展示。

## 12. 最终实施顺序

1. 保持后端当前实现和接口文档作为前端开发基线。
2. 先做前端类型和 API 封装。
3. 再做路由、对话页管理员入口和后台侧栏入口。
4. 再做上传、状态轮询和并发控制。
5. 再做文档列表、端点列表和删除能力。
6. 再做手动检索和结果展示。
7. 最后做体验收口、移动端适配、lint、build、Playwright 和人工回归。

当前计划只确定前端开发方案，不在本阶段执行前端代码开发。
