# OpenAPI 智能助手整合计划

## 1. 最终决策

### 1.1 整合目标

将 `SmartApiAgent/backend/` 中的 OpenAPI 文档解析、知识库检索和接口调用辅助能力整合进个人博客网站 `backend/`。整合后，管理员可以在博客后台上传 OpenAPI 文档、维护共享知识库，并在博客现有 AI 对话中让 AI 基于该知识库回答接口问题或生成调用示例。

### 1.2 固定边界

1. 后端架构以博客网站 `backend/` 为准。
2. 不迁移 SmartApiAgent 的独立 FastAPI 应用壳、独立配置、独立会话存储、独立聊天入口。
3. 不迁移 SmartApiAgent 的 SSE 流式对话；继续使用博客现有阻塞式 `POST /api/v1/ai_chat/chat`。
4. 不使用 Chroma；OpenAPI 向量知识库统一落到 PostgreSQL + pgvector。
5. 不引入 SmartApiAgent 的 `asyncpg` 双层会话记忆；继续使用博客现有 `ChatService`、`ai_conversations`、`conversation_messages` 和 Redis checkpointer。
6. OpenAPI 文档解析、知识库更新、知识库检索、代码生成、代码检查、子 Agent 编排等能力只允许管理员及以上使用。
7. 普通用户不能通过 REST 接口、Agent 工具、Prompt 或前端入口知道或触发 OpenAPI 私有知识库能力。
8. Agent 编排、工具注册、Prompt 组装、权限治理全部沿用博客现有 `create_agent`、`ToolRegistry`、`PromptAssemblyMiddleware` 体系。
9. 新功能实施必须按 TDD：先写失败测试，再实现，再回归。

### 1.3 已定技术选择

| 决策项 | 最终选择 |
|--------|----------|
| 后端模块名 | `openapi_knowledge` |
| 对话方式 | 阻塞式复用 `/api/v1/ai_chat/chat` |
| 向量库 | PostgreSQL + pgvector |
| 文档解析任务 | 不单独建任务表；OpenAPI 文档表自身承载解析状态 |
| 解析状态查询 | 通过 `GET /api/v1/openapi_knowledge/documents/{document_id}` 轮询 |
| 管理员工具 | 注册为 `ToolScope.ADMIN` |
| Prompt 权限注入 | `permission_level` 写入 `ChatState`，由 `PromptAssemblyMiddleware` 读取 |
| SmartApiAgent Supervisor | 不迁移为主图；后续复杂能力只作为管理员工具或内部服务调用 |
| MCP SSE | 不作为博客前台能力迁入 |

## 2. 当前系统理解

### 2.1 博客后端现有基础

博客后端已经具备整合所需的主干能力：

1. FastAPI 主应用统一挂载 `/api/v1`。
2. JWT 登录认证通过 `get_current_user` 获取当前用户。
3. 权限等级为 `USER=0`、`ADMIN=1`、`SUPER_ADMIN=2`。
4. `require_admin` 已能保护管理员接口。
5. AI 对话由 `ChatService` 管理，接口为 `POST /api/v1/ai_chat/chat`。
6. 对话历史持久化到 `ai_conversations` 和 `conversation_messages`。
7. LangGraph Agent 通过 `get_chat_graph(permission_level)` 编译，并按权限过滤工具。
8. `ToolRegistry.resolve(permission_level)` 已支持 `ToolScope.ADMIN`。
9. `PromptAssemblyMiddleware` 已负责每轮动态组装 System Prompt。
10. 博客文章 RAG 已使用 PostgreSQL + pgvector 和统一 Embedding 客户端。

### 2.2 SmartApiAgent 可复用能力

仅复用以下能力思想或局部实现：

1. OpenAPI/Swagger 文档按 `path + method` 拆分端点。
2. JSON/YAML 文档解析。
3. `$ref` 基础展开。
4. 端点文本中保留 path、method、summary、description、parameters、requestBody、responses、schema。
5. 基于端点文本做 Embedding 检索。
6. 基于检索结果回答 API 用法问题。
7. 基于检索结果生成调用示例。
8. 原有测试样例可改造成博客后端测试。

明确不复用：

1. 独立 `/api/v1/chat` SSE 对话。
2. `create_sse_response` 和 SSE 消息模型。
3. Chroma `VectorStore`。
4. `memory_manager`、SmartApiAgent 的 Redis/PG 聊天历史。
5. 独立 DeepSeek/DashScope 配置字段。
6. 无鉴权知识库接口。
7. 内存 `task_store`。

| `backend/app/models/openapi_document.py` | OpenAPI 文档元数据与解析状态 |

| `backend/app/crud/openapi_knowledge.py` | 文档与端点 CRUD |

| `backend/app/services/openapi_embedding_service.py` | 端点向量同步、检索、删除 |
| `backend/app/graphs/nodes/toolnodes/openapi_search.py` | 管理员 OpenAPI 检索工具 |
| `backend/app/graphs/nodes/toolnodes/openapi_codegen.py` | 管理员 OpenAPI 调用示例生成工具 |

### 3.2 数据模型

#### OpenAPI 文档表

表名：`openapi_documents`

| 字段 | 说明 |
|------|------|
| `id` | 主键，也是对外 `document_id` |
| `uploaded_by` | 上传管理员用户 ID |
| `filename` | 原始文件名 |
| `content_hash` | 原始文件 hash，用于重复上传检测 |
| `status` | `pending`、`processing`、`completed`、`failed` |
| `endpoint_count` | 解析出的端点数量 |
| `chunk_count` | 写入向量的分片数量 |
| `error_message` | 解析失败原因 |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |

文档记录就是解析任务记录，不再设计独立 task 表。上传接口返回 `document_id`，前端用文档详情接口轮询 `status`。

#### OpenAPI 端点向量表

表名：`openapi_endpoint_embeddings`

| 字段 | 说明 |
|------|------|
| `id` | 主键 |
| `document_id` | 所属 OpenAPI 文档 ID |
| `chunk_id` | 端点分片唯一 ID |
| `path` | API 路径 |
| `method` | HTTP 方法 |
| `summary` | OpenAPI summary |
| `description` | OpenAPI description 摘要 |
| `tags` | 标签，使用 JSONB 存储 |
| `operation_id` | OpenAPI operationId |
| `content` | 用于 RAG 的端点文本 |
| `embedding` | pgvector 向量 |
| `content_hash` | 端点内容 hash |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |

索引要求：

1. `embedding` 使用 HNSW + cosine。
2. `document_id` 建普通索引。
3. `method` 建普通索引。
4. `chunk_id` 唯一。

删除策略：

1. 删除文档时级联删除该文档下所有端点向量。
2. 删除单个端点只删除对应向量记录。

## 4. 权限与 Prompt 设计

### 4.1 三层权限控制

1. REST API 层：所有 `/api/v1/openapi_knowledge/*` 接口必须依赖登录用户，并调用 `require_admin(current_user)`。
2. 工具注册层：OpenAPI 检索、调用示例生成、后续代码检查或子 Agent 工具全部注册为 `ToolScope.ADMIN`。
3. Prompt 层：只有管理员对话状态中注入 OpenAPI 能力说明；普通用户 Prompt 不出现 OpenAPI 私有知识库能力。

### 4.2 Prompt 权限链路

必须补齐以下链路：

1. 在 `ChatState` 增加 `permission_level: int | None`。
2. 在 `ChatService.chat()` 调用 `self.graph.ainvoke()` 的 payload 中加入 `permission_level=self.permission_level`。
3. 在 `PromptAssemblyMiddleware` 中读取 `state.get("permission_level")`。
4. 扩展 `render_chat_system_prompt()`，根据 `permission_level >= ADMIN` 追加管理员 OpenAPI 能力说明。
5. 普通用户 `permission_level=0` 时，渲染结果必须不包含 OpenAPI、接口知识库、代码生成子 Agent 等私有能力描述。

管理员 Prompt 只追加高层级能力和约束：

1. 你拥有访问已上传 OpenAPI 文档知识库的权限，可基于知识库回答接口相关问题或生成调用示例。
2. 如果知识库没有相关文档，明确说明“当前知识库未找到相关接口”，不要编造参数。
3. 不向非管理员透露后台 OpenAPI 知识库、工具或子 Agent 能力。
4. 具体工具调用时机和参数以工具自身描述为准。

### 4.3 工具描述要求

OpenAPI 工具 docstring 必须说明：

1. 工具只对管理员可见。
2. 什么问题应触发工具。
3. 什么问题不应触发工具。
4. 无检索结果时不得编造参数、路径、请求体或响应体。
5. 返回内容必须是模型可读的摘要文本，不直接暴露复杂原始 JSON。

## 5. 接口规划

### 5.1 接口概览

| 序号 | 方法 | 路径 | 功能简述 | 调用方 |
|------|------|------|----------|--------|
| 1 | POST | `/api/v1/openapi_knowledge/documents/upload` | 上传 OpenAPI 文档并启动后台解析 | 管理员后台 |
| 2 | GET | `/api/v1/openapi_knowledge/documents` | 分页查看文档列表 | 管理员后台 |
| 3 | GET | `/api/v1/openapi_knowledge/documents/{document_id}` | 查看文档详情和解析状态 | 管理员后台 |
| 4 | DELETE | `/api/v1/openapi_knowledge/documents/{document_id}` | 删除文档及端点向量 | 管理员后台 |
| 5 | GET | `/api/v1/openapi_knowledge/endpoints` | 分页查看端点列表 | 管理员后台 |
| 6 | GET | `/api/v1/openapi_knowledge/search` | 手动检索 OpenAPI 知识库 | 管理员后台 |
| 7 | DELETE | `/api/v1/openapi_knowledge/endpoints/{endpoint_id}` | 删除单个端点向量 | 管理员后台 |

不提供 `/tasks/{task_id}`。解析进度由文档自身 `status` 表示，前端轮询 `GET /documents/{document_id}`。

### 5.2 枚举

| 枚举 | 值 | 说明 |
|------|----|------|
| `OpenAPIDocumentStatus` | `pending` | 文档已创建，等待解析 |
| `OpenAPIDocumentStatus` | `processing` | 后台正在解析和向量化 |
| `OpenAPIDocumentStatus` | `completed` | 解析和向量入库完成 |
| `OpenAPIDocumentStatus` | `failed` | 解析或向量入库失败 |

### 5.3 接口定义

#### POST `/api/v1/openapi_knowledge/documents/upload`

上传 `.json`、`.yaml`、`.yml` OpenAPI 文档，创建 `openapi_documents` 记录并启动后台解析。

权限要求：管理员及以上。

请求：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `file` | file | 是 | OpenAPI/Swagger 文档，限制 10MB |

成功响应：

```json
{
  "document_id": 1,
  "filename": "openapi.yaml",
  "status": "pending"
}
```

失败：

| 状态码 | 原因 |
|--------|------|
| 400 | 未上传文件、空文件、格式不支持 |
| 401 | 未登录 |
| 403 | 非管理员 |
| 413 | 文件超过大小限制 |

#### GET `/api/v1/openapi_knowledge/documents`

分页查看 OpenAPI 文档列表。

权限要求：管理员及以上。

Query：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `skip` | int | 否 | 默认 0 |
| `limit` | int | 否 | 默认 20，上限 100 |
| `status` | string | 否 | 按状态过滤 |

#### GET `/api/v1/openapi_knowledge/documents/{document_id}`

查看单个文档详情和解析状态。前端上传后通过该接口轮询，不再查询独立 task。

权限要求：管理员及以上。

成功响应包含：

| 字段 | 说明 |
|------|------|
| `id` | 文档 ID |
| `filename` | 原始文件名 |
| `status` | 当前解析状态 |
| `endpoint_count` | 端点数量 |
| `chunk_count` | 向量分片数量 |
| `error_message` | 失败原因 |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |

#### DELETE `/api/v1/openapi_knowledge/documents/{document_id}`

删除文档及其所有端点向量。

权限要求：管理员及以上。

成功响应：`204 No Content`。

#### GET `/api/v1/openapi_knowledge/endpoints`

分页查看端点列表。

权限要求：管理员及以上。

Query：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `skip` | int | 否 | 默认 0 |
| `limit` | int | 否 | 默认 50，上限 200 |
| `document_id` | int | 否 | 按文档过滤 |
| `method` | string | 否 | 按 HTTP 方法过滤 |
| `tag` | string | 否 | 按标签过滤 |

#### GET `/api/v1/openapi_knowledge/search`

管理员手动检索 OpenAPI 知识库。

权限要求：管理员及以上。

Query：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `q` | string | 是 | 检索问题或关键词 |
| `top_k` | int | 否 | 默认 5，上限 20 |
| `method` | string | 否 | 可选 HTTP 方法过滤 |
| `document_id` | int | 否 | 可选文档过滤 |

#### DELETE `/api/v1/openapi_knowledge/endpoints/{endpoint_id}`

删除单个端点向量。

权限要求：管理员及以上。

成功响应：`204 No Content`。

## 6. 分阶段实施

### 阶段 0：基线保护

1. 运行当前后端测试，记录基线。
2. 补充工具权限测试：普通用户只得到公共工具，管理员得到管理员工具。

4. 补充 `include_hidden=true` 仅管理员可用的回归测试。

验收标准：

1. 当前 AI 对话、博客检索、联网搜索不回归。
2. 普通用户不可见管理员工具的底线有测试保护。

### 阶段 1：数据模型与 SQL 文档

1. 新增 `openapi_documents` ORM 模型。
2. 新增 `openapi_endpoint_embeddings` ORM 模型。
3. 编写 `sql/openapi_documents.md`。
4. 编写 `sql/openapi_endpoint_embeddings.md`。

验收标准：

1. ORM、SQL 文档、测试字段一致。
2. 删除文档能级联删除端点向量。

### 阶段 2：解析服务

1. 实现 `OpenAPIParserService`。
2. 支持 JSON/YAML。
3. 支持 OpenAPI 3.x 基础结构。
4. 支持 Swagger 2.0 的基础 paths 结构；复杂兼容不足时返回明确错误或记录限制。
5. 按 `path + method` 生成端点分片。
6. 展开基础 `$ref`。
7. 生成端点 `content_hash`。

测试先行：

1. JSON 文档可解析。
2. YAML 文档可解析。
3. 空 paths 返回零端点。
4. 非法 JSON/YAML 返回明确错误。
5. 基础 `$ref` 能展开 object/array。

### 阶段 3：上传与后台解析

1. 新增 `POST /documents/upload`。
2. 上传时创建 `openapi_documents` 记录，初始状态为 `pending`。
3. 后台任务开始时状态改为 `processing`。
4. 解析和向量入库成功后状态改为 `completed`。
5. 失败时状态改为 `failed`，写入 `error_message`。
6. 新增 `GET /documents/{document_id}` 作为解析状态查询接口。
7. 不实现 `/tasks/{task_id}`。

测试先行：

1. 普通用户上传返回 `403`。
2. 管理员上传返回 `document_id`。
3. 非支持格式返回 `400`。
4. 解析失败后文档状态为 `failed`。

### 阶段 4：向量入库与检索

1. 实现 `OpenAPIEmbeddingService`。
2. 复用博客 `get_embedding_client()`。
3. 批量向量化端点文本。
4. 使用 pgvector cosine distance 检索。
5. 支持 `top_k`、相似度阈值、`method`、`document_id` 过滤。
6. 实现手动检索接口。

测试先行：

1. 空 query 返回参数错误。
2. 普通用户检索返回 `403`。
3. 管理员检索返回结构化结果。
4. 低于阈值的结果被过滤。

### 阶段 5：管理员 Agent 工具

1. 新增 `search_openapi_docs` 工具。
2. 新增 `generate_openapi_call_example` 工具。
3. 两个工具都注册为 `ToolScope.ADMIN`。
4. 工具内部调用 `OpenAPIEmbeddingService`。
5. 工具返回模型可读文本，不返回原始复杂 JSON。
6. 知识库为空或无匹配时明确说明，禁止编造接口参数。

1. `ToolRegistry.resolve(0)` 不包含 OpenAPI 工具。

3. 管理员工具调用能返回格式化检索结果。

## 8. 风险与约束

1. 权限不能只靠 Prompt，必须同时落实到 REST、工具注册和 Prompt。
2. `permission_level` 如果不写入 `ChatState`，管理员 Prompt 无法可靠按权限渲染。
3. OpenAPI 文档可能包含内部接口、鉴权参数和示例 token，接口和工具结果必须仅管理员可见。
4. 向量维度必须与当前 Embedding 模型一致。
5. 大型 OpenAPI 文档会带来 embedding 成本，需要文件大小限制、批量处理和 content hash 去重。
6. Swagger 2.0 和复杂 schema 组合能力要通过测试逐步补齐，不在第一版中隐式承诺完全覆盖。
7. 修改 `ChatState`、`PromptAssemblyMiddleware`、`ChatService.chat()` 会影响现有 AI 对话，必须做回归测试。

## 9. 实施顺序

1. 先补权限、Prompt、工具注册的保护测试。
2. 再做数据库模型和 SQL 文档。
3. 再做解析服务和文档状态流转。
4. 再做 pgvector 入库和检索。
5. 再注册管理员 Agent 工具。
6. 再补接口文档、SQL 文档、目录文档并完成后端回归。
7. 最后再接前端后台页面，并做前端 lint、build、Playwright 与全量验收。
